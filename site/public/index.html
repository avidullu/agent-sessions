Agent Sessions is a local-first archive for AI pair-programming history. It discovers sessions across your coding agents, exports them to plain Markdown, and keeps one deduplicated, searchable catalog — on your disk, under your rules.

Why this exists

The most valuable output of an AI session never reaches your repo

A coding session with an AI agent contains the why that a commit never captures: the constraints you stated, the approaches you rejected, the bug that took forty minutes to corner, the review feedback you gave and got. Multiply that across Claude Code, Codex, Gemini, and a VS Code extension or three, and you have a real engineering record —

…scattered across app-data directories in undocumented formats, readable only inside each vendor's UI, and quietly pruned whenever a tool feels like it. Switch machines and it fragments further. Switch tools and it is simply gone.

Session history should outlive the tool that produced it — in a format you can grep, diff, back up, and read in twenty years.

Design rationale

Five principles, applied strictly

Local-first, or it doesn't ship

No cloud storage, no telemetry, no network calls during export. Your transcripts never leave your machine unless you move them yourself.

Plain artifacts

Markdown transcripts plus a JSONL catalog. Everything is greppable, diffable, and versionable — no database, no proprietary viewer.

Deterministic extraction

Each agent gets a purpose-built extractor held to a frozen output contract, so two machines produce byte-identical renders of the same session.

Privacy by design

Redaction quarantines high-confidence secrets; home directories are stored as portable ~ paths; a CI gate keeps real user paths out of anything tracked.

One catalog, many agents

Content-hash identity dedupes the same session exported from Windows and WSL, keeps sibling sessions apart, and merges VS Code agents through a sidecar contract.

Architecture

Two small tools, one contract

agent-session-router (VS Code extension)     agent-sessions (Python CLI hub)
  discovers VS Code agent sessions             discovers CLI agent sessions
  extracts messages                            extracts messages
  renders Markdown (contract v1)               renders Markdown + PDF (contract v1)
  writes .router-index.jsonl sidecar  ───────▶ merges sidecar → archive/index.jsonl
  auto-watches for new sessions                baseline: suggest → promote → publish

The router covers agents that live inside VS Code storage; the hub covers CLI agents and owns the catalog. Either works standalone — the output contract is the bridge, and both repos vendor the same golden fixtures so the two implementations cannot drift.

Quick start

Five minutes to your first archive

# Install the hub
pip install agent-session-hub

# See what's on this machine
agent-archive discover --write docs/DISCOVERY.md

# Export everything to Markdown + catalog
agent-archive export --all

# Freshness and convergence signals
agent-archive status

Full setup — including the VS Code extension, PDF export, and daily automation — is in GETTING_STARTED.md.

Beyond archiving

From transcripts to institutional memory

Once sessions are catalogued, the baseline pipeline mines them: it proposes handoff summaries and guardrails from what actually happened (suggest), lets you curate what deserves to persist (promote), and publishes the result as tracked, reviewable Markdown (publish). An experimental rules-extraction track goes further, distilling recurring corrections and preferences into candidate standing rules for your agents — with an efficacy harness measuring recall against real sessions, and echo-contamination controls so agents don't launder their own boilerplate into "your preferences."

Honest limits

What it deliberately does not do

  • No hosting. Both tools are local-first; there is no server component to trust.
  • No perfect redaction. Redaction catches high-confidence secrets and placeholders home paths — review transcripts before sharing them anyway.
  • No built-in search engine. The catalog is plain text; bring your own grep, or a companion indexer.
  • No rewrite ambitions. The router stays TypeScript, the hub stays Python; the contract is the bridge.
