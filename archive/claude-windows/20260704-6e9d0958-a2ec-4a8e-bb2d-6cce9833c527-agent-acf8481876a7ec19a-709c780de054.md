Line 79: `entries = data.get("videos", data) if isinstance(data, dict) else data`

This handles two cases:
- If `data` is dict with key "videos", use `data["videos"]`
- If `data` is dict without "videos", use `data` itself
- If `data` is not dict, use `data`

Then line 80 checks `if not isinstance(entries, list)` and raises. This means the fallback path `if isinstance(data, dict) else data` can only work if the dict case has no "videos" key AND `data` itself is a list. But that's contradictory—if `data` is a dict, it can't also be a list. **This branch is unreachable dead code.** The line should be:
```python
entries = data.get("videos", data) if isinstance(data, dict) else data
```
But the `if isinstance(data, dict) else data` part only makes sense if we expect a bare list at the top level, yet the loop later checks `if not isinstance(entry, dict)` suggesting entries ARE expected to be dicts. The condition is over-protective.
