## Windows Installation with Docker

Windows is not officially supported, but some users have had success getting it to run under WSL or Virtualbox. Getting the GPU and/or Coral devices properly passed to Frigate may be difficult or impossible. However, some users have been able to get Frigate running with Nvidia GPU Tensor, as well as the Google Coral USB on Windows via WSL 2 and Docker Desktop.

Frigate runs best with Docker installed on bare metal Debian-based distributions. For ideal performance, Frigate needs low overhead access to underlying hardware for the Coral and GPU devices.

## FFmpeg Integration

The low-resolution feed is routed to the FFmpeg Decoder, where it is decoded using Hardware Acceleration (HW Accel) to minimize CPU usage. ffmpeg has been updated to version 7. For hardware acceleration, if you are using hardware acceleration for ffmpeg, you may need to use the Full Access variant of the App. This is because the Frigate App runs in a container with limited access to the host system. The Full Access variant allows you to disable Protection mode and give Frigate full access to the host system.

## ML Detectors and Models

Frigate supports multiple detector types and models:

**Detector Types:** Frigate recommends using a USB Google Coral for this task, but you may also choose to use a NVIDIA GPU with TensorRT (supported on post-Pascal GPUs only). Additionally, OpenVINO will automatically be detected and used as a detector in the default Frigate image when a supported ONNX model is configured. Nvidia GPUs will automatically be detected and used as a detector in the -tensorrt Frigate image when a supported ONNX model is configured. TensortRT can run on Jetson devices, using one of many default models. ONNX: TensorRT will automatically be detected and used as a detector in the -tensorrt-jp6 Frigate image when a supported ONNX model is configured.

**Model Conversion:** Once built, copy the .onnx file to your /config/model_cache folder. Frigate will automatically convert this to a TensorRT engine on the first boot. The replacement for TensorRT, the ONNX detector, no longer ships with prebuilt models—even if you're using the 0.16.x-tensorrt images. In other words: you now have to provide your own models.

**Recommended Models:** YOLO-NAS or YOLOv9 are recommended as they provide superior performance and accuracy compared to the models supported by TensorRT.

**Multiple Detectors:** When using many cameras one detector may not be enough to keep up. Multiple detectors can be defined assuming GPU resources are available.

Ollama automatically detects NVIDIA GPUs via CUDA and AMD GPUs via DirectML on Windows. For NVIDIA specifically, you need to update to the latest Game Ready or Studio driver (version 527+) and ensure CUDA is installed. Ollama automatically uses your GPU when CUDA is available.
