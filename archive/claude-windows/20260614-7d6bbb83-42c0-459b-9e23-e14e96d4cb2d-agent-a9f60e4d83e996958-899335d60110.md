## What is Point-Supervised Temporal Action Localization?

Point-supervised temporal action localization (PSTAL) is a task that provides a timestamp label for each action instance to balance labeling cost and model performance. Models are trained with a single-frame annotation for each untrimmed video.

## Key Characteristics

Point-level temporal action localization aims to localize actions in untrimmed videos with only one timestamp annotation for each action instance. This approach offers practical advantages over fully-supervised methods, as annotators only watch the video once to record the action class and timestamp, making the annotation process almost the same as weakly-supervised annotation.

## Technical Approaches

Research in this area has explored different paradigms:

- The proposal-based prediction paradigm offers a more constrained solution space with consistent predictions among neighboring frames, using point-level annotations as keypoint supervision to train a keypoint detector.

- Some methods use the single-frame label to mine adjacent pseudo labels for training classifiers.

- Other approaches search for optimal pseudo sequences through greedy algorithms to guide networks in learning action instance completeness.

The key challenge is that frame-level prediction paradigms suffer from a large solution space when learning from sparse single-frame labels.

## Overview

Mean average precision (mAP) at different thresholds of temporal intersection over union (tIoU) is the most common metric used in action detection.

## How tIoU Works

Intersection over union (tIoU) is a 1-dimensional temporal Jaccard similarity metric and is computed as the ratio of the intersection of the predicted and actual duration of an action to their union. A predicted temporal bounding box is considered to be correct if its temporal IoU with the ground-truth instance is larger than a certain threshold and the predicted category is the same as this ground-truth instance.

## Standard Thresholds by Dataset

Different datasets use different threshold sets:

- **THUMOS14**: mAP with tIoU thresholds set {0.3, 0.4, 0.5, 0.6, 0.7} is used.

## Calculation

At a specified tIoU, Average Precision is calculated for every action class and then averaged up to mAP@tIoU.

# Distributional Bias in Leave-One-Out Cross-Validation

## The Core Mechanism

Distributional bias emerges from a mathematical inevitability: when you remove one sample as a test instance in LOOCV, the training set's label mean shifts inversely. For binary classification with overall positive rate μ, removing a positive sample changes the training mean to μN/(N-1), while removing a negative sample changes it to (μN-1)/(N-1). This creates "a negative correlation between the average label of each training fold and the label of its corresponding test instance."

The effect is dramatic enough that a dummy predictor returning the *negative* of the training set mean achieves perfect auROC scores on random data—pure information leakage.

## Why Regression to the Mean Amplifies the Problem

Machine learning models naturally predict values close to their training data's average. When distributional bias systematically shifts that average in inverse correlation with held-out labels, models with stronger regularization suffer most. They're more prone to predicting near-mean values, so they get disproportionately penalized by the label distribution mismatch.

## Impact on Performance Evaluation and Hyperparameter Selection

The authors demonstrated that logistic regression evaluated via standard LOOCV on random data yielded auROC scores of 0.23—far below the 0.5 expected for random guessing. This bias doesn't just underestimate performance; it systematically favors weaker regularization during hyperparameter tuning, since stronger regularization amplifies mean-regression effects.

## Recommended Mitigation: Rebalanced LOOCV (RLOOCV)

The paper proposes removing an additional training sample with the *opposite* label of each held-out test instance, ensuring constant class balance across training folds. This maintains i.i.d. assumptions and eliminates distributional shifts without risking performance inflation.

For your tiny-dataset scenario, this matters significantly because weaker signals amplify bias effects.
