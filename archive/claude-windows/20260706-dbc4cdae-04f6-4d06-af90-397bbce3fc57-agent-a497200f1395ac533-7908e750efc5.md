# WASB: Widely Applicable Strong Baseline for Sports Ball Detection and Tracking

Code & dataset repository for the paper: **[Widely Applicable Strong Baseline for Sports Ball Detection and Tracking](https://arxiv.org/abs/2311.05237)**

Shuhei Tarashima, Muhammad Abdul Haq, Yushan Wang, Norio Tagawa

[![arXiv](https://img.shields.io/badge/arXiv-2311.05237-00ff00.svg)](https://arxiv.org/abs/2311.05237) [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT) ![test](https://img.shields.io/static/v1?label=By&message=Pytorch&color=red)

We present Widely Applicable Strong Baseline (WASB), a Sports Ball Detection and Tracking (SBDT) baseline that can be applied to wide range of sports categories :soccer: :tennis: :badminton: :volleyball: :basketball: .

https://github.com/nttcom/WASB-SBDT/assets/63090948/8889ef53-62c7-4c97-9b33-8bf386489ba1

## 4. Torch 1.11 → 2.x compatibility risks

- **`torch.load` `weights_only` — REAL BREAK RISK.** `src/detectors/detector.py` line 58 calls `checkpoint = torch.load(model_path)` with **no `weights_only=` argument**, then `self._model.load_state_dict(checkpoint['model_state_dict'])`. On **torch ≥ 2.6** the default flipped to `weights_only=True`. Whether this raises depends on what's pickled in the `.pth.tar`: a plain tensor/state-dict dict loads fine, but if the checkpoint pickled any non-tensor objects (e.g. numpy scalars, argparse/OmegaConf objects, custom classes) it will raise `UnpicklingError`/`WeightsUnpickler error`. **Mitigation is trivial:** pass `weights_only=False` (trusted file) or add safe globals. `src/models/hrnet.py` line 495 has a second bare `torch.load(pretrained)` in `init_weights()`, but that path is only hit when loading an ImageNet-pretrained backbone during training, not during the eval/inference flow. Source: `src/detectors/detector.py`, `src/models/hrnet.py`.
- **hydra-core / omegaconf pins — LOW-MODERATE risk.** The repo pins `hydra-core==1.2.0` (which pulls `omegaconf` ~2.2). This is an old Hydra; it generally still installs on modern Python but Hydra 1.2 + newer omegaconf/pydantic-free stacks can conflict. Config code uses `HydraConfig.get().run.dir` (stable API). No omegaconf version is pinned directly. Recommend upgrading to hydra-core ≥1.3 and re-testing config resolution. Source: `Dockerfile`, `src/detectors/detector.py`.
- **Removed/renamed torch APIs — LOW risk for this HRNet code.** The HRNet implementation uses only stable ops: `nn.BatchNorm2d(..., momentum=BN_MOMENTUM)`, `nn.Conv2d`, `nn.init.kaiming_normal_`, and `nn.DataParallel`. I found **no** use of the classic HRNet footguns (`F.upsample`, `Variable`, `.volatile`, `async`, `.data[...]`). The main friction points are: (a) `nn.DataParallel` still works but is deprecated in favor of DDP; (b) upsampling in HRNet fusion typically needs an explicit `align_corners=` — not a hard break, but numerics can shift. Overall the model code should port to torch 2.x with minimal changes; the checkpoint-load default is the one thing most likely to fail out of the box. Source: `src/models/hrnet.py`, `src/detectors/detector.py`.
