# muneem — Testing Strategy

> Status: **active.** Companion to [`ROADMAP.md`](./ROADMAP.md) (sequencing) and [`../DESIGN.md`](../DESIGN.md) (architecture + threat model). This doc owns *how we know muneem works* — and, just as importantly, *how we know it isn't leaking or hallucinating*.
>
> Created 2026-05-30. Grounded in a direct inspection of the committed promo corpus (`testdata/promo-emails/`), not in the abstract.

---

## 1. Principles

1. **Grounded, not aspirational.** Every test tier below maps to a failure mode actually observed in the real corpus (§ 2), not a hypothetical one.
2. **Precision ranks with recall.** A bookkeeper that invents a promo code or a transaction is worse than one that misses it. Negative fixtures (no code present) are first-class.
3. **Test on safe data by default.** The committed promo corpus is non-sensitive and drives CI. Sensitive paths (statements) are tested on **synthetic/redacted fixtures** in CI and on **local-only, gitignored** real data behind an opt-in marker — never real statements in CI or the repo.
4. **CI is offline, deterministic, secretless.** No network, no cloud LLM, no OAuth, no keychain in the default CI run. Non-deterministic steps (OCR, LLM) are mocked/cassette-backed by default and exercised live only behind explicit markers.
5. **Security posture is enforced by tests, not just docs.** Redaction, category-gating of cloud LLMs, and "no sensitive paths tracked in git" are assertions that fail the build (§ 9).
6. **Adding a corpus file means adding its answer-key entry.** The corpus and its ground truth move together (§ 4).

---

### Gotchas the real data exposes (each becomes a test)

- **Ligatures in the text layer.** PyMuPDF returns `Oﬀer` / `Oﬀ` (U+FB00 `ﬀ`), not `Offer`/`Off`. Naïve substring/regex matching for "Off"/"Offer" silently fails. → **NFKC normalization** before matching, with a dedicated unit test (`airasia-2`, `airasia-3`).
- **Codes live in images about half the time.** 6 of 10 PDFs carry the offer in rasterized banners (`bigimgs` ≥ 1 and an empty/near-empty text layer). OCR is not optional for the corpus; it is the path for ~half of it.
- **Expiry is rarely a clean date.** Observed forms: absolute-ish ("before July 31st"), relative ("Ends Today", "Final Day!", "Last few hours left"), conditional ("≥15 days in advance"), and a **live countdown timer**. → Expiry parsing must resolve relative phrases against the email's *received date* and tolerate "no hard date."
- **Filename ≠ issuer.** `airasia-1.pdf` is an **Air India Express** mailer. → Issuer detection must derive from sender/content, never the filename. (Also: fix the mislabel in the corpus README.)
- **Third-party PII in fixtures.** Recipient is `Ayush Raina <ayushraina767@gmail.com>` (the prototype's tester, *not* the muneem user), and bodies are personalized ("…left Ayush!"). The corpus README says "no PII beyond the recipient's email address"; in reality the recipient is a *different person* and appears in the body. Treated as **non-sensitive** (promo, already committed, no financial data), but extraction tests must not surface or log it as financial PII, and golden files (§ 5) intentionally retain it as committed non-sensitive content.

## 3. Fixture tiers (derived from § 2)

The corpus self-stratifies into capability tiers. Tests are gated by tier so CI stays green and honest about what's proven.

| Tier | Capability under test | Members | CI behavior |
|---|---|---|---|
| **T1 — text-layer codes** | Deterministic extraction, no OCR | `dataquest`, `makemytrip-2` | **Must pass** in default CI (recall + precision = 100%). |
| **T2 — image-only codes** | OCR (Tesseract) → code recovery | `swiggy` (+ any unverified row confirmed image-coded) | Behind `@pytest.mark.ocr`; runs in the optional OCR job, skipped if the Tesseract binary is absent. |

| **T4 — unverified** | Answer key not yet established | the 6 ⚠️ rows | `@pytest.mark.xfail(strict=False)` until verified in A.4; never block CI on guesses. |
