## 1. NVIDIA DALI — end-to-end GPU video pipeline → PyTorch

- **End-to-end GPU decode + resize/normalize, on-device:** DALI can decode video on the GPU (NVDEC) and run `fn.resize` / `fn.crop_mirror_normalize` on GPU, keeping data on-device through to the framework handoff. The video decoder "utilizes either libavcodec (FFmpeg) or NVIDIA Video Codec SDK (NVDEC) for decoding the frames." When run with `device="mixed"`, demuxing is on CPU and frame decode runs on NVDEC/GPU. Source: [fn.experimental.decoders.video docs](https://docs.nvidia.com/deeplearning/dali/user-guide/docs/operations/nvidia.dali.fn.experimental.decoders.video.html) (via search snippet) and [DALI GitHub README](https://github.com/NVIDIA/DALI) which shows `decode data on the GPU`, `fn.resize()`, `fn.crop_mirror_normalize()`, and PyTorch conversion.
- **Operators (as asked):**
  - `fn.experimental.decoders.video` — decodes from in-memory encoded video; backends libavcodec or NVDEC; output is a frame sequence with shape **(F, H, W, C)** (FHWC layout). [Docs](https://docs.nvidia.com/deeplearning/dali/user-guide/docs/operations/nvidia.dali.fn.experimental.decoders.video.html)

## 5. GPU resize + YUV→RGB color convert, and color-parity notes

- **DALI:** GPU resize via `fn.resize`; YUV→RGB conversion happens in the decoder/`fn.color_space_conversion`. **Color parity caveat:** DALI's YCbCr conversions follow **ITU-R BT.601** by default ("DALI's image decoder will decode to RGB and then convert to YCbCr, following the YCbCr definition from ITU-R BT.601"). A real color-mismatch bug report exists: [issue #4441 "Color space discrepancy on video"](https://github.com/NVIDIA/DALI/issues/4441) — a BT.470BG, full-range test video decoded by DALI differed (histogram) from the source; the user asked "What is the actual color space used by the DALI decoder?" - **PyNvVideoCodec:** Outputs RGB/RGBP directly (YUV→RGB on the GPU decode path). **On-device resize/scaling is NOT documented as a built-in feature** — the API programming guide "does not explicitly mention on-device GPU resize or scaling." For GPU resize you pair it with **CV-CUDA**. It exposes a `colorspace` param (`bt601` / `bt709`) but the docs surface this **for ARGB/ABGR encode inputs**, not clearly as a decode-side selector — **open question** whether decode-side BT.601/709 and limited/full range are user-selectable. NVDEC-based decoders can pick the matrix from stream metadata (often BT.709 for HD). **Practical implication:** frames from a GPU decoder (DALI/PyNvVideoCodec via NVDEC) can differ from cv2's output by a **BT.601-vs-BT.709 and limited-vs-full-range** shift — do not assume pixel-exact parity; verify per-pipeline.
