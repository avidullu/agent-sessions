1	# Rally Annotator
2	
3	[![tests](https://github.com/avidullu/rally-annotator/actions/workflows/ci.yml/badge.svg)](https://github.com/avidullu/rally-annotator/actions/workflows/ci.yml)
4	
5	A tiny **VLC plugin** to hand-label rally **start/end + point-stop reason** while you watch a match,
6	for **net-separated racquet sports** — badminton, tennis, table tennis, pickleball, padel.
7	
8	You watch the video in VLC, pause/scrub freely, and click **Mark START** / **Mark END** (with a
9	reason). It writes one CSV row per rally — clean ground-truth labels for training/evaluating rally
10	(point) segmentation models, or just for cutting highlights.
11	
12	```
13	rally_number,start_time,end_time,ending_reason,sport,shots_count
14	1,8.800,11.500,winner,badminton,9
15	2,24.389,46.589,unforced_error,badminton,21
16	```
17	
18	Times are **decimal seconds**; `shots_count` is an **optional** rally shot/stroke count (blank if you skip it).
19	See [docs/CSV_FORMAT.md](docs/CSV_FORMAT.md).
20	
21	## Why
22	Labeling rally boundaries is the slow, expensive prerequisite for any rally-detection model. Most tools
23	make you transcribe timestamps by hand. This lets a rater do it **inside the player they already use**,
24	pausing to the exact frame before each mark — turning "watch a match" into "produce golden labels."
25	
26	## Install
27	1. Copy `vlc/rally_annotator.lua` into your VLC Lua **extensions** folder:
28	   - **Windows:** `%APPDATA%\vlc\lua\extensions\`
29	   - **macOS:** `~/Library/Application Support/org.videolan.vlc/lua/extensions/`
30	   - **Linux:** `~/.local/share/vlc/lua/extensions/`
31	   (create the `extensions` folder if it doesn't exist)
32	2. In VLC: **Tools → Plugins and extensions → Reload extensions** (or just restart VLC).
33	3. Enable it from the **View** menu → **Rally Annotator**. A small dialog opens and stays open while you watch.
34	
35	Requires **VLC 3.0.x**. (VLC 4.0 changed the Lua input/listener API; targeting 3.x for now.)
36	
37	## Use
38	**Playback is built in** — the **Back 5s · Play / Pause · Fwd 5s** row drives the VLC player from the
39	annotation window, so you can pause, label, and resume without ever switching to the main VLC window. **Play / Pause**
40	is a single toggle (it resumes when paused, pauses when playing).
41	
42	1. Pick the **Sport** (it stays set across rallies).
43	2. When a rally begins, click **Mark START** — it snapshots the current playback time into the **Start** field
44	   (pause/scrub first for frame accuracy; you can also edit the field by hand).
45	3. When the rally ends, click **Mark END** (fills the **End** field). This *arms* the rally; nothing is written yet.
46	4. Choose the **Ending reason** (sits between **Mark END** and **Save Rally**; defaults to **`unknown`**), optionally
47	   type a **Number of shots** (the rally's shot/stroke count — leave blank to skip), then click
48	   **Save Rally** to write one CSV row. The reason **resets to `unknown` after every save** (and the shots field
49	   clears too) — so neither silently reuses the previous rally's value, and you can pick the same reason on
50	   consecutive rallies. Use the **Next rally #** field to resume/insert numbering anywhere.
51	5. **Recent rallies** list: select a row, then **Edit selected** (loads it back into the fields to fix
52	   start/end/reason/sport → **Save changes**) or **Delete selected**. **Undo last** removes the most recent row —
53	   the button shows which one, e.g. `Undo last (#7)`, and the status panel shows that row's details — or clears an
54	   in-progress mark, or cancels an edit.
55	6. **Help** button → usage + an [ending-reason decision guide](docs/ENDING_REASONS.md), rendered inside the dialog.
56	
57	**Output:** `<video-stem>.rallies.csv` next to the video (falls back to your home dir if the path can't be
58	resolved). Re-opening the extension **continues** rally numbering from the existing file — no duplicate IDs.
59	
60	**Resuming a half-finished video:** labels are saved to that CSV as you go. Open the **same video** and enable the
61	extension and it **reloads your existing rallies** (shown in the Recent list) and continues numbering — so you can
62	stop and pick up later. Easiest flow: **open the video first, then enable the extension.** If you enable it *before*
63	the video is loaded, that's fine too — the moment you click **Mark START** (the video is playing by then) the tool
64	switches to that video's own `<video-stem>.rallies.csv` and loads any rallies already saved for it, so nothing is
65	written to the home-dir fallback by mistake. If you switch videos with the dialog already open, click **Refresh** to
66	point at the current video and load its rallies. (Playback *position* isn't restored — scrub to where you stopped.)
67

69	> Add-ons** is VLC's own add-on info dialog; its body ("Lua script") is a constant baked into VLC and **can't be
70	> set by an extension**. Use the **Help** button inside the Rally Annotator dialog instead. (The descriptor's

74	## Sports & taxonomy
75	Net-separated racquet sports share a forced/unforced-error point-stop taxonomy, so one tool covers them all:
76	
77	| Sport | Notes |
78	|---|---|
79	| badminton | the reference sport |
80	| tennis | service_fault = fault/double-fault; let supported |
81	| table_tennis | let (net serve) supported; fast cadence |
82	| pickleball | service_fault for faults; treat "let" per local rules |
83	| padel | net-separated; rally boundaries as in tennis |
84	
85	`ending_reason` ∈ `{unknown, winner, forced_error, unforced_error, service_fault, let, other}` — a shared
86	vocabulary across these sports. Keep to these values for clean downstream aggregation.
87	
88	### What the ending reasons mean
89	`unknown` is the **default** (the field resets to it after every save); every other reason **except `winner`** is
90	charged to the side that **lost** the rally.
91	
92	| Reason | When the rally ended because… |
93	|---|---|
94	| `unknown` | **default** — not classified yet. A save with no reason picked records `unknown` (never the previous rally's reason); set a specific reason when you can. |
95	| `winner` | the last shot landed **in** and went unreturned (opponent couldn't reach it / only waved). A clean ace counts here. |
96	| `forced_error` | the loser **missed** (out or into the net) while **under pressure** — stretched, rushed, jammed, handling the opponent's pace/spin/depth. |
97	| `unforced_error` | the loser **missed a routine shot** they had time **and** position to make, with little or no pressure. |
98	| `service_fault` | the point ended **on the serve** — into the net, out of the service box, illegal action/foot fault, or a double fault. |
99	| `let` | the rally is **replayed** under the rules, no point scored (e.g. a tennis/table-tennis serve net-cord that's otherwise good, outside interference). |
100	| `other` | none of the above — occluded footage, injury/retirement, penalty, hindrance. Use sparingly. |
101	
102	**The cases people ask about:** a ball/shuttle landing **out** is the *hitter's* error → `forced_error` only if they
103	were under pressure, otherwise `unforced_error` (it's **never** automatically forced, and never a winner for the
104	opponent). **Into the net** during a rally is the same; a **serve** into the net is `service_fault`. When unsure
105	forced-vs-unforced, **default to `unforced_error`**. See the full decision guide with examples and per-sport rules
106	in **[docs/ENDING_REASONS.md](docs/ENDING_REASONS.md)** (also available via the in-plugin **Help** button).

1	# Ending reasons — what they mean & how to label them
2	
3	The `ending_reason` column records **why the rally (point) ended**, judged from the
4	**last shot**. There are seven values, shared across all the net-separated racquet sports
5	this tool supports (badminton, tennis, table tennis, pickleball, padel):
6	
7	```
8	unknown | winner | forced_error | unforced_error | service_fault | let | other
9	```
10	
11	**`unknown` is the default** — the annotator resets the reason to `unknown` after every save, so a
12	rally you didn't classify is honestly recorded as `unknown` (never the previous rally's reason). Set a
13	specific reason when you can; `unknown` simply marks rallies still needing a verdict.
14	
15	**One core principle:** every reason **except `winner`** (and the neutral `unknown`) is charged to the
16	player/side that **LOST** the rally. `winner` is the only one that credits the side that **won** it.
17	
18	This guide is written for a human rater clicking through a match. Where a rule comes from
19	the laws of the sport it is marked **[rule]**; where it is an analytics *convention* (a
20	judgement call that charters agree to apply consistently) it is marked **[convention]**.
21	
22	---
23	
24	## The decision procedure (top to bottom — stop at the first match)
25	
26	1. **Was the rally replayed under the rules, with no point scored?**
27	   (e.g. a tennis/padel serve that clips the net and lands in the correct box; a table-tennis
28	   serve that touches the net and is otherwise good; outside interference; receiver not ready.)
29	   → **`let`**. *A net-cord during open rally play that lands in is NOT a let — keep going.*
30	
31	2. **Did the point end on the SERVE because of a server fault?**
32	   (serve into the net, serve outside the correct service court, illegal service action / foot
33	   fault, or a tennis/padel **double fault**.)
34	   → **`service_fault`**.
35	
36	3. **Did the winning side's last shot land IN and go unreturned** — the opponent couldn't
37	   reach it, or only waved at it without meaningful contact? (A clean untouched serve / **ace**
38	   counts here.) → **`winner`**.
39	
40	4. **Otherwise the rally ended on a MISS by the loser** (ball/shuttle **out**, **into the net**,
41	   or not legally returned). Now judge **pressure**:
42	
43	   > **The pressure test:** Did the loser have **both enough time AND court position** to make a
44	   > routine return, given the opponent's *immediately preceding* shot (its placement, pace,
45	   > power, spin, depth, angle)? Ask: *"Would a typical competent player at this level be
46	   > expected to make that shot?"* **[convention]**
47	
48	   - **Yes** — had time and position, missed a routine ball → **`unforced_error`**.
49	   - **No** — time or position was taken away; the miss was induced → **`forced_error`**.
50	
51	5. **Can't judge it, or it ended off-court** (occluded footage, injury/retirement, code/point
52	   penalty, hindrance, equipment failure) → **`other`**. Use sparingly.
53	
54	**Tie-breaker [convention]:** when you genuinely can't tell forced from unforced, **default to
55	`unforced_error`**. Only mark `forced_error` when you can *point to the specific pressure* (the
56	wide/fast/deep/spinny ball that removed the player's time or position). This keeps `forced_error`
57	a positively-evidenced label and stops it from inflating. The forced/unforced boundary is a real
58	*continuum* — charters disagree on borderline calls, so fix the default in writing for your team.
59	
60	---
61	
62	## The six reasons, defined
63	
64	### `winner`
65	The point-ending shot landed **in** and the opponent did **not** make a meaningful return
66	(couldn't reach it, or only waved). Credit to the side that won the rally. A clean untouched
67	legal serve (an **ace**) is conventionally a `winner`, not a `service_fault`.
68	*Examples:* a smash that bounces untouched; a deceptive drop the opponent never reaches; a
69	passing shot down the line.
70	*Not a winner:* if the opponent reaches it but mishits **under pressure**, that is **their**
71	`forced_error`, not your `winner`.
72	
73	### `forced_error`
74	A miss by the **loser** (out, into the net, or not legally returned) where the opponent's
75	previous shot applied enough pressure — placement, pace, power, spin, depth, angle — that the
76	player did **not** have time *and* position for a routine return. They were *made* to miss.
77	*Examples:* a wide, heavy serve return netted while lunging at full stretch; a hard smash dug up
78	but floated long because the player was off-balance and rushed.
79	
80	### `unforced_error`
81	A miss by the **loser** on a shot they had **time AND position** to make routinely, with little
82	or no pressure. They gave it away.
83	*Examples:* a comfortable mid-court ball drilled into the net; a relaxed clear pushed past the
84	back line; a sitter smashed long.
85	
86	### `service_fault`
87	A fault by the **server on the serve itself** that loses the point or the serve — judged against
88	the sport's *service* rules, not general rally play. Includes: serve into the net, serve out of
89	the correct service court/box, illegal service action (e.g. badminton contact above 1.15 m,
90	ITTF illegal toss, pickleball illegal motion), foot fault, and a tennis/padel **double fault**.
91	*Note:* a **first**-serve fault followed by a good second serve is **not** charged here — only the
92	serve that actually loses the point is. A clean ace is a `winner`, not a `service_fault`.
93	
94	### `let`
95	A **replay** defined by the laws, where **nobody is charged** a point — the rally "didn't count":
96	a tennis/padel service net-cord that still lands in the correct box (replayed, unlimited times);
97	a table-tennis serve that touches the net and is otherwise correct; an outside interruption; the
98	receiver not ready. Use **only** when the rule says *replay*.
99	*Caution:* a net-cord during a **rally** (not the serve) that lands in is live — **not** a `let`.
100	
101	### `other`
102	Catch-all for endings that fit none of the above: the outcome is genuinely unclear/occluded on
103	video; or the point ended administratively (injury retirement, code/point penalty, hindrance
104	call, equipment failure) rather than on a struck shot. Prefer a specific category whenever the
105	footage supports it.
106	
107	---
108	
109	## The cases people ask about most
110	
111	These are the calls that trip raters up — resolved precisely.
112	
113	### A. The ball/shuttle lands **OUT** (past the baseline or outside the sidelines)
114	This is **always the hitter's error** — the side that **lost** the rally. The opponent merely let
115	it sail (or it cleared the line untouched), so it is **never** the opponent's `winner`. Decide
116	`forced` vs `unforced` purely by **pressure on the hitter** at the moment they struck it — look at
117	the opponent's *previous* shot, not the out ball itself:
118	- Rushed, stretched, off-balance, or handling heavy pace/spin/depth → **`forced_error`**.
119	- Set and balanced, with time on a routine ball, and still sprayed it → **`unforced_error`**.
120	
121	"Beyond the baseline" vs "outside the sideline" doesn't change the logic — both are *out*, both are
122	the hitter's miss. (In tennis and badminton the **line is in**; this applies only when it lands
123	fully outside.) **So "out" is not automatically `forced`** — that label needs visible pressure;
124	otherwise it's `unforced`.
125	
126	### B. The ball/shuttle goes **INTO the net** (fails to cross)
127	Same as an "out" ball — it's the hitter's error, and the **pressure test** decides: `forced_error`
128	if they were rushed/stretched, `unforced_error` if they dumped a routine ball.
129	**Exception:** if the failure-to-cross happens **on the serve**, it is a **`service_fault`** (in
130	tennis/padel, a missed second serve = double fault), not a rally error — the rally never legally
131	began.
132	
133	### C. The **net-cord / net tape** (ball or shuttle clips the top)
134	- **During a rally:** it is **live and good** in all of these sports. Play continues, so the rally
135	  ends on whatever happens **next**: if the opponent can't reach the dribbler → it's a `winner`
136	  (a "net-cord winner"); if they scramble and then miss → judge *that* miss as forced/unforced.
137	  A rally net-cord is **never** a `let`.
138	- **On the serve — sports differ:**
139	  | Sport | Serve clips the net and… |
140	  |---|---|
141	  | **Tennis / Padel** | …lands in the correct box → **`let`** (replay). Lands outside → `service_fault`. |
142	  | **Table tennis** (ITTF) | …is otherwise correct → **`let`** (serve replayed). |
143	  | **Badminton** (BWF) | …passes over and lands in the service court → **live, play on** (no service let). But a serve shuttle **caught/suspended on the net** is a **`service_fault`** (BWF Law 13.2), *not* a let. |
144	  | **Pickleball** (2026 USAP) | …lands in the correct court → **live, play on** (the old service-let was removed). Lands out → `service_fault`. |
145	
146	---
147	
148	## Sport-specific notes
149	
150	- **Tennis (ITF):** double fault → `service_fault`; service net-cord into the box → `let`; lines
151	  are **in**; a clean ace → `winner`.
152	- **Badminton (BWF):** service contact must be with the whole shuttle below **1.15 m** from the
153	  court surface (Law 9.1.6; the older "above the waist" wording is the alternative trial law). A
154	  shuttle landing outside the lines or failing to pass the net is a fault; a **serve caught on the
155	  net is a fault** (`service_fault`), while a mid-rally suspended shuttle (Law 14.2.3, only *after*
156	  the serve is returned) is a `let`. Lines are **in**.
157	- **Table tennis (ITTF):** a serve touching the net assembly but otherwise correct is a **`let`**
158	  (replayed); in a rally, a ball that touches the net and still lands on the opponent's court is a
159	  **good return**.
160	- **Pickleball (USAP 2026):** **no** service let — a net-clip that lands in the correct court is
161	  live; illegal serve motion / net-clip-out → `service_fault`.
162	- **Padel (FIP):** like tennis for the serve net-cord `let`. Wall play means a rally ball off the
163	  glass after one bounce is still live. (One edge case — a let-bound serve that touches the net and
164	  then the side **wire mesh** before its 2nd bounce — is finicky; verify against current FIP text.)

332	  end
333	  os.remove(bak)
334	  return true
335	end

538	-- Re-resolve the CSV path against whatever video is playing NOW and load its
539	-- labels. Lets the user open a video later (or switch videos) and pick up exactly
540	-- where they left off without toggling the extension off/on. Same video -> just
541	-- re-read the CSV; a different video -> repoint and load that video's rallies.
542	local function sync_to_current_video()
543	  if mode == "edit" then
544	    -- Reloading rows would invalidate edit_index; make the user resolve the edit first.
545	    refresh_list(); refresh_buttons()
546	    set_status("Finish (Save changes) or cancel (Undo last) the current edit before refreshing.")
547	    return
548	  end
549	  local media = current_media_path()
550	  if not media then
551	    refresh_list(); refresh_buttons()
552	    set_status("No media is playing -- still using this CSV. Open the video, then click Refresh.")
553	    return
554	  end
555	  out_path_is_fallback = false   -- a video is playing now -> we have a real path
556	  local new_path = resolve_out_path()
557	  if new_path == out_path then
558	    load_rows()                  -- re-read in case the file changed on disk
559	    refresh_next_field()
560	    refresh_list(); refresh_buttons()
561	    set_status(string.format("Refreshed. %d rallies loaded for this video.", #rows))
562	    return
563	  end
564	  out_path = new_path            -- switched videos -> repoint + resume that file
565	  load_rows()
566	  reset_form()
567	  refresh_next_field()
568	  refresh_list()
569	  refresh_buttons()
570	  set_status(string.format(
571	    "Switched to the current video. Loaded %d existing rallies; next is #%d.", #rows, next_rally_number()))
572	end

574	-- Lazily adopt the playing video's CSV. We may have started on the home-dir FALLBACK
575	-- (extension enabled before the video was loaded, so no path was resolvable then). The
576	-- moment a timestamp exists the video is provably playing, so switch to <video>.rallies.csv
577	-- and load that video's existing rallies BEFORE anything is written to the fallback -- this
578	-- is what makes "enable, then open the video" and pause/restart resume correctly instead of
579	-- silently writing to ~/rally_labels.csv. No-op once we're already on a real video CSV.
580	local function adopt_current_video_csv()
581	  if not out_path_is_fallback then return end
582	  local media = current_media_path()
583	  if not media then return end           -- still no video -> stay on the fallback for now
584	  out_path_is_fallback = false           -- a real path is resolvable now
585	  local p = resolve_out_path()
586	  if p == out_path then return end       -- already pointing there (defensive)
587	  out_path = p
588	  load_rows()                            -- pick up rallies already saved for this video
589	  refresh_next_field()
590	  refresh_list()
591	end

593	-- Seek the player by delta_s seconds (relative), clamped at 0 (time is microseconds in 3.x).
594	local function seek_by(delta_s)
595	  local input = vlc.object.input()
596	  if not input then set_status("No media playing -- cannot seek."); return end
597	  local t = vlc.var.get(input, "time")   -- microseconds
598	  if not t then set_status("No playback time available to seek from."); return end
599	  local nt = t + delta_s * 1000000
600	  if nt < 0 then nt = 0 end
601	  vlc.var.set(input, "time", nt)
602	  set_status(string.format("Seek %+ds  ->  %s.", delta_s, fmt_clock(nt / 1000000.0)))
603	end

608	function mark_start()
609	  local t = now_seconds()
610	  if not t then set_status("No media playing -- cannot mark START."); return end

614	    return
615	  end

617	  w_start:set_text(string.format("%.3f", t))
618	  refresh_buttons()
619	  set_status(string.format("START set @ %s. Play to the rally's end, then Mark END.", fmt_clock(t)))

630	function save_rally()
631	  adopt_current_video_csv()   -- in case times were typed by hand without Mark START
632	  local s = get_field_num(w_start)
633	  local e = get_field_num(w_end)
634	  if not s then set_status("Set a START time first (click Mark START)."); return end
635	  if not e then set_status("Set an END time first (click Mark END)."); return end
636	  if e < s then s, e = e, s end   -- tolerate reversed marks
637	  if e <= s then
638	    set_status("END must be later than START (rally must be > 0s).")
639	    return
640	  end
641	  local _, reason = w_reason:get_value()   -- (id, text); "unknown" is allowed
642	  if not reason or reason == "" then reason = REASON_DEFAULT end
643	  local _, sport = w_sport:get_value()
644	  if not sport or sport == "" then sport = SPORTS[1] end
645	  local shots = get_shots()                -- optional; nil when blank
646	  local shots_note = (shots ~= nil) and string.format(", %d shots", shots) or ""
647	
648	  local msg
649	  if mode == "edit" and edit_index and rows[edit_index] then
650	    local r = rows[edit_index]
651	    r.s, r.e, r.reason, r.sport, r.shots = s, e, reason, sport, shots
652	    local ok, err = save_all()
653	    if not ok then set_status("WRITE FAILED: " .. tostring(err)); return end
654	    msg = string.format("Updated rally #%d: %s -> %s  [%s, %s%s].", r.n, fmt_clock(s), fmt_clock(e), reason, sport, shots_note)
655	  else
656	    local n = planned_next_number()
657	    if index_of_rally(n) then
658	      set_status(string.format("Rally #%d already exists -- set \"Next rally #\" to a free number.", n))
659	      return
660	    end
661	    rows[#rows + 1] = { n = n, s = s, e = e, reason = reason, sport = sport, shots = shots }
662	    local ok, err = save_all()
663	    if not ok then rows[#rows] = nil; set_status("WRITE FAILED: " .. tostring(err)); return end
664	    if w_next then w_next:set_text(tostring(next_free_from(n + 1))) end   -- next free number
665	    msg = string.format("Saved rally #%d: %s -> %s  [%s, %s%s].", n, fmt_clock(s), fmt_clock(e), reason, sport, shots_note)
666	  end
667	
668	  reset_form()       -- clears fields + resets the (required) reason to placeholder
669	  refresh_list()
670	  set_status(msg)
671	end

710	  if mode == "edit" then
711	    reset_form(); refresh_list(); set_status("Edit cancelled.")
712	    return
713	  end

715	  local e = get_field_num(w_end)

728	  refresh_buttons()

737	-- (playlist_TogglePause), so we branch on status() to keep one Play / Pause button
738	-- deterministic: pause() flips playing<->paused, and from stopped we play() fresh.
739	function play_pause()
740	  local st = vlc.playlist.status()
741	  if st == "playing" then
742	    vlc.playlist.pause()        -- toggles playing -> paused
743	    set_status("Paused. Annotate (or fine-tune Start/End), then Play / Pause to resume.")
744	  elseif st == "paused" then
745	    vlc.playlist.pause()        -- toggles paused -> playing
746	    set_status("Resumed playback.")
747	  elseif st == "stopped" then
748	    vlc.playlist.play()
749	    set_status("Started playback.")
750	  else
751	    set_status("No media loaded to play.")
752	  end
