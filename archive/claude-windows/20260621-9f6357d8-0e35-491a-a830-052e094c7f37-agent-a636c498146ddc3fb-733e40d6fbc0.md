50	
51	### 2.1 The "by design" invariant — no hardcoded user-facing strings
52	
53	Every coach-facing string is a **stable key** resolved at render time against the active locale.
54	Code references `t("compile.button")`, never the English prose. This is the single rule that
55	makes "add a language = add a catalog" true, and it is **enforced by CI** (§2.6) so it cannot
56	silently regress as the codebase grows.
57	
58	```
59	"Validate & Index Video"                         →  t("video.action.validate_index")
60	alert("Validation Failed! …review the checklist") →  t("toast.validation_failed")
61	`${count} Rally Segment${count>1?'s':''} Selected`→  t("compile.selected", {count})   # ICU plural
62	HTTPException(detail="Video file not found at …")→  detail = tr(lang, "error.video_not_found", {path})
63	```
64	
65	### 2.2 One canonical English source catalog, per-locale siblings
66	
67	```
68	locales/
69	  en/  common.json   # source of truth — devs author keys here
70	  kn/  common.json   # Kannada  (Gemini-draft → human-review)
71	  hi/  common.json   # Hindi    (next; first exercise of the extensibility checklist)
72	```
73

75	  the SPA, with no conversion.

77	  This matters immediately — the current UI already hand-rolls English plurals
78	  (`Rally Segment${count > 1 ? 's' : ''}`), and Kannada/Hindi plural rules differ from English.
79	  ICU encodes each language's rules in the catalog, not the code.

- **But for an offline/air-gapped bundle this lazy-by-unicode-range model breaks down:** you must ship **the entire chunk set** so any string renders without a network fetch. Plan for **~5–16 MB per CJK language per weight on disk** in the bundle. With 3 CJK languages (SC, JP, KR) × even 1–2 weights, that's **tens of MB** added to an otherwise small bundle — this is the dominant size cost of this whole project and the reason CJK is phased last.
- **Mitigations:** (a) use the **variable** `@fontsource-variable` packages (one file spans all weights, avoids N× per-weight duplication); (b) consider **building a custom subset** restricted to the glyphs your reviewed `zh-Hans/ja/ko` catalogs + dynamic data (rally counts, dates) actually use — for a small fixed UI this can cut a CJK font from MBs to tens of KB, at the cost of a build step that must re-run whenever catalog text changes; (c) **lazy-load CJK font CSS per active locale** so non-CJK users never download it (works for online; for true air-gapped you still ship everything but only load on demand).

### 5. Rendering / layout gotchas
- **Thai — no spaces between words.** Thai uses spaces as *phrase* delimiters, not word delimiters, so naive wrapping breaks mid-word. Browsers do dictionary-based line breaking but it's imperfect. Mitigations: `word-break: normal` + `overflow-wrap: break-word` as a safety net, optionally `line-break: loose/auto`, and avoid forcing breaks. Thai also has stacking combining marks (vowels/tones above/below) — ensure line-height has headroom so diacritics aren't clipped.
- **CJK line-breaking** can break between (almost) any two characters, which is mostly fine, but watch **kinsoku** (forbidden line-start/end punctuation) — `line-break: strict` improves this. CJK glyphs are taller/denser; give generous `line-height`. CJK generally has **no italic** and reacts poorly to faux-bold — rely on the variable-weight axis, not `font-style: italic`.
- **Spanish string expansion** — expect **~15–30% longer** than English (and occasional longer single words). Buttons/labels/toasts must not be fixed-width or truncate; test the longest Spanish strings. (Your current `Rally Segment(s) Selected → t("compile.selected",{count})` plural key is exactly the kind of element to stress-test.) Danish is similar but milder; Indonesian is roughly English-length.
- **CJK/Thai are more *compact* horizontally** than Latin, so the risk is the opposite (lots of whitespace), not overflow — but ensure your layout doesn't assume a minimum string length either.

## Recommended phasing

Order by *least new code/assets first*, then *one script-block font*, then *the heavy CJK + script-variant decision last*:

- **Phase A — Latin trio (catalog-only, zero new code/assets): `es`, `da`, `id`.**
  No font, no lazy-loading, no bundle-size impact. The *only* engineering touch is making your ICU plural authoring + key-parity/lint check handle **Spanish's 3-form `{one, many, other}`** (Danish/Indonesian are 2-form/1-form and trivially fit existing tooling). Best first slice: highest ROI, proves the catalog pipeline scales beyond Indic without code changes. Spanish is the only one needing reviewer attention (the `many` arm).
- **Phase B — Thai (`th`): one new small OFL font.**
  Add **Noto Sans Thai** (`@fontsource-variable/noto-sans-thai`) — small, single-script, no subsetting drama; reuses the exact font-bundling pattern you already established for Noto Kannada/Devanagari. Single-form plural (`other`). Add the Thai no-space word-wrap CSS safety net. Self-contained, low-risk.
- **Phase C — CJK (`zh-Hans`, `ja`, `ko`): the heavy slice — needs new code/assets + a product decision.**
  Requires: (1) the **`zh-Hans` vs `zh-Hant` decision** (recommend ship `zh-Hans` only first); (2) **3 large OFL Noto fonts** (SC/JP/KR); (3) **per-locale lazy-loading of font CSS** so non-CJK users aren't penalized; (4) for the **offline/air-gapped bundle, a CJK subsetting build step** (or accept tens of MB). All single-form plural (`other`), so catalog authoring is the easy part — the work is fonts + loading, not strings. Do this last and as its own PR(s); consider one PR per CJK language given the font weight.
