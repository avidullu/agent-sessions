6	> **Part of [Khelsutra](https://khelsutra.guru) — _“Every rally, indexed. The dead time, gone.”_**
7	> Khelsutra turns a full badminton match into a clean index of rallies with the dead time stripped out —
8	> a highlight reel you can watch and download. **Rally Annotator is its open labeling tool**: the
9	> ground-truth rally CSVs produced here are what the Khelsutra pipeline trains and evaluates its
10	> rally-segmentation models against. This repo is the public, open-source piece of that stack.
11	
12	Hand-label rally **start/end + point-stop reason** while you watch a match, for **net-separated racquet
13	sports** — badminton, tennis, table tennis, pickleball, padel. Two front-ends, **same CSV**:
14	
15	- 🎬 **VLC plugin** — label **local video files** inside VLC (this README); the dialog is **localized**
16	  (English, Hindi, Kannada, Telugu, Spanish, Danish, Indonesian) via a Language selector.
17	- 🌐 **Browser extension** _(new)_ — label **web video, including YouTube**, right in the page;
18	  **localized into English, Hindi, Kannada, Telugu, Spanish, Danish & Indonesian**. See **[web/](web/)**.
19	
20	You watch the video in VLC, pause/scrub freely, and click **Mark START** / **Mark END** (with a
21	reason). It writes one CSV row per rally — clean ground-truth labels for training/evaluating rally
22	(point) segmentation models, or just for cutting highlights.
23	
24	```
25	rally_number,start_time,end_time,ending_reason,sport,shots_count
26	1,8.800,11.500,winner,badminton,9
27	2,24.389,46.589,unforced_error,badminton,21
28	```
29	
30	Times are **decimal seconds**; `shots_count` is an **optional** rally shot/stroke count (blank if you skip it).

33	## Generating rally annotations — pick your front-end
34	
35	| You're labeling… | Use | Output |
36	|---|---|---|
37	| a **local video file** | the **VLC plugin** (install + use below) | `<video>.rallies.csv` next to the file |
38	| **web video / YouTube** (`youtube.com/watch`) | the **browser extension** → [web/](web/) | the full CSV downloaded on each save |

45	## Why
46	Labeling rally boundaries is the slow, expensive prerequisite for any rally-detection model. Most tools
47	make you transcribe timestamps by hand. This lets a rater do it **inside the player they already use**,
48	pausing to the exact frame before each mark — turning "watch a match" into "produce golden labels."

61	## Use
62	**Playback is built in** — the **Back 5s · Play / Pause · Fwd 5s** row drives the VLC player from the
63	annotation window, so you can pause, label, and resume without ever switching to the main VLC window. **Play / Pause**
64	is a single toggle (it resumes when paused, pauses when playing).
65	
66	1. Pick the **Sport** (it stays set across rallies).
67	2. When a rally begins, click **Mark START** — it snapshots the current playback time into the **Start** field
68	   (pause/scrub first for frame accuracy; you can also edit the field by hand).
69	3. When the rally ends, click **Mark END** (fills the **End** field). This *arms* the rally; nothing is written yet.
70	4. Choose the **Ending reason** (sits between **Mark END** and **Save Rally**; defaults to **`unknown`**), optionally
71	   type a **Number of shots** (the rally's shot/stroke count — leave blank to skip), then click
72	   **Save Rally** to write one CSV row. The reason **resets to `unknown` after every save** (and the shots field
73	   clears too) — so neither silently reuses the previous rally's value, and you can pick the same reason on
74	   consecutive rallies. Use the **Next rally #** field to resume/insert numbering anywhere.
75	5. **Recent rallies** list: select a row, then **Edit selected** (loads it back into the fields to fix
76	   start/end/reason/sport → **Save changes**) or **Delete selected**. **Undo last** removes the most recent row —
77	   the button shows which one, e.g. `Undo last (#7)`, and the status panel shows that row's details — or clears an
78	   in-progress mark, or cancels an edit.
79	6. **Help** button → usage + an [ending-reason decision guide](docs/ENDING_REASONS.md), rendered inside the dialog.
80	
81	**Output:** `<video-stem>.rallies.csv` next to the video (falls back to your home dir if the path can't be
82	resolved). Re-opening the extension **continues** rally numbering from the existing file — no duplicate IDs.
83	
84	**Resuming a half-finished video:** labels are saved to that CSV as you go. Open the **same video** and enable the
85	extension and it **reloads your existing rallies** (shown in the Recent list) and continues numbering — so you can
86	stop and pick up later. Easiest flow: **open the video first, then enable the extension.** If you enable it *before*
87	the video is loaded, that's fine too — the moment you click **Mark START** (the video is playing by then) the tool
88	switches to that video's own `<video-stem>.rallies.csv` and loads any rallies already saved for it, so nothing is
89	written to the home-dir fallback by mistake. If you switch videos with the dialog already open, click **Refresh** to
90	point at the current video and load its rallies. (Playback *position* isn't restored — scrub to where you stopped.)

98	## Sports & taxonomy
99	Net-separated racquet sports share a forced/unforced-error point-stop taxonomy, so one tool covers them all:
100	
101	| Sport | Notes |
102	|---|---|
103	| badminton | the reference sport |
104	| tennis | service_fault = fault/double-fault; let supported |
105	| table_tennis | let (net serve) supported; fast cadence |
106	| pickleball | service_fault for faults; treat "let" per local rules |
107	| padel | net-separated; rally boundaries as in tennis |
108	
109	`ending_reason` ∈ `{unknown, winner, forced_error, unforced_error, service_fault, let, other}` — a shared
110	vocabulary across these sports. Keep to these values for clean downstream aggregation.
111	
112	### What the ending reasons mean
113	`unknown` is the **default** (the field resets to it after every save); every other reason **except `winner`** is
114	charged to the side that **lost** the rally.
115	
116	| Reason | When the rally ended because… |
117	|---|---|
118	| `unknown` | **default** — not classified yet. A save with no reason picked records `unknown` (never the previous rally's reason); set a specific reason when you can. |
119	| `winner` | the last shot landed **in** and went unreturned (opponent couldn't reach it / only waved). A clean ace counts here. |
120	| `forced_error` | the loser **missed** (out or into the net) while **under pressure** — stretched, rushed, jammed, handling the opponent's pace/spin/depth. |
121	| `unforced_error` | the loser **missed a routine shot** they had time **and** position to make, with little or no pressure. |
122	| `service_fault` | the point ended **on the serve** — into the net, out of the service box, illegal action/foot fault, or a double fault. |
123	| `let` | the rally is **replayed** under the rules, no point scored (e.g. a tennis/table-tennis serve net-cord that's otherwise good, outside interference). |
124	| `other` | none of the above — occluded footage, injury/retirement, penalty, hindrance. Use sparingly. |
125	
126	**The cases people ask about:** a ball/shuttle landing **out** is the *hitter's* error → `forced_error` only if they
127	were under pressure, otherwise `unforced_error` (it's **never** automatically forced, and never a winner for the
128	opponent). **Into the net** during a rally is the same; a **serve** into the net is `service_fault`. When unsure
129	forced-vs-unforced, **default to `unforced_error`**. See the full decision guide with examples and per-sport rules
130	in **[docs/ENDING_REASONS.md](docs/ENDING_REASONS.md)** (also available via the in-plugin **Help** button).

14	export interface RallyRow {
15	  n: number; // rally_number (integer, 1-based, monotonic)
16	  s: number; // start_time, decimal seconds
17	  e: number; // end_time, decimal seconds (> s)
18	  reason: string; // ending_reason
19	  sport: string;
20	  shots: string | null; // shots_count token verbatim (e.g. "9"); null when blank
21	  extra: string | null; // columns 7+ joined verbatim; null when none
22	}
23	
24	export const HEADER =
25	  "rally_number,start_time,end_time,ending_reason,sport,shots_count\n";
26	
27	// Mirror Lua tonumber(): trims, "" -> nil, non-numeric -> nil. (NB: JS Number("")
28	// is 0 and Number("  1 ") is 1, so we must special-case empty after trimming.)
29	function luaToNumber(x: string | undefined): number | null {
30	  if (x == null) return null;
31	  const t = x.trim();
32	  if (t === "") return null;
33	  const v = Number(t);
34	  return Number.isNaN(v) ? null : v;
35	}
36	
37	// Rewrite the whole CSV from rows (header once) — mirrors save_all(). The browser
38	// has no atomic tmp+rename; durability is handled by the IndexedDB live store
39	// (see persist layer), with this serialized form as the downloadable artifact.
40	export function serializeRows(rows: RallyRow[]): string {
41	  let out = HEADER;
42	  for (const r of rows) {
43	    const shots = r.shots != null ? r.shots : "";
44	    let line = `${Math.trunc(r.n)},${r.s.toFixed(3)},${r.e.toFixed(3)},${r.reason},${r.sport},${shots}`;
45	    if (r.extra != null && r.extra !== "") line += "," + r.extra;
46	    out += line + "\n";
47	  }
48	  return out;
49	}
50	
51	// Forgiving parse — mirrors load_rows(): any line whose first field is an integer
52	// is a rally row; header and blank lines are skipped; column 6 is the optional
53	// shots_count (blank/missing in older CSVs); columns 7+ are kept verbatim.
54	export function parseRows(text: string): RallyRow[] {
55	  const rows: RallyRow[] = [];
56	  for (const raw of text.split(/\n/)) {
57	    const line = raw.replace(/\r$/, "");
58	    if (!/\S/.test(line)) continue; // skip blank lines
59	    const parts = line.split(",");
60	    const nRaw = luaToNumber(parts[0]);
61	    if (nRaw == null || nRaw !== Math.floor(nRaw)) continue; // not a row (e.g. header)
62	    let shots: string | null = parts[5] ?? null;
63	    if (shots === "") shots = null; // blank => not recorded
64	    // NB: the LOAD default for a missing/blank reason is "other" (distinct from the
65	    // in-app SAVE default of "unknown"); preserved here exactly as in load_rows().
66	    const reason = parts[3] != null && parts[3] !== "" ? parts[3] : "other";
67	    const extra = parts.length > 6 ? parts.slice(6).join(",") : null;
68	    rows.push({
69	      n: Math.floor(nRaw),
70	      s: luaToNumber(parts[1]) ?? 0,
71	      e: luaToNumber(parts[2]) ?? 0,
72	      reason,
73	      sport: parts[4] ?? "",
74	      shots,
75	      extra,
76	    });
77	  }
78	  return rows;
79	}
