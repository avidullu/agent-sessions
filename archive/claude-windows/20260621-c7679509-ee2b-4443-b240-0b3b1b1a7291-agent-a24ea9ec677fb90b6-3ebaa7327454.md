# Docker Compose GPU Request Mechanism

## How Compose Requests GPUs

Docker Compose requests GPUs through the `deploy.resources.reservations.devices` specification within service definitions in the `compose.yaml` file.

## Device Properties Syntax

The `devices` attribute supports four configurable properties:

1. **`driver`**: Specifies the GPU driver (e.g., `'nvidia'`) as a string value.

2. **`capabilities`**: A list of strings defining GPU capabilities. For example, `capabilities: [gpu]` grants GPU access to the container.

3. **`count`**: An integer or `'all'` value indicating how many GPUs to reserve. If not specified, all available GPUs are used by default.

4. **`device_ids`**: A list of strings representing specific GPU device IDs from the host, obtainable via `nvidia-smi`.

5. **`options`**: Key-value pairs for driver-specific configurations.

## Is `capabilities` Mandatory?

Yes. The documentation states: "You must set the `capabilities` field. Otherwise, it returns an error on service deployment."

## Can You Combine `count` and `device_ids`?

No. The documentation explicitly notes: "`count` and `device_ids` are mutually exclusive. You must only define one field at a time." Attempting to combine both will generate an error.

- **Backward compatibility** involves running older applications on newer drivers
