292	def _probe_video_fps_width(path: str):
293	    """Robust ffprobe (fps, frame_width) for a real video. Returns None on ANY failure.
294	
295	    The detector trajectory is frame-indexed; the harness maps frame->time via fps, so a WRONG
296	    fps silently mis-aligns every rally label (e.g. a 60fps clip read as 30 doubles every time).
297	    cv2's ``_probe_fps_width`` silently defaults to (30, 1280) on a read miss — fine for the
298	    inference report (it flags the fallback) but corrupting for REAL training data. So here we
299	    probe with ffprobe (same tool as ``get_video_duration``) and return None so the caller SKIPS
300	    rather than guesses.
301	    """
302	    import json
303	    import subprocess
304	    try:
305	        out = subprocess.check_output(
306	            [ffprobe_bin(), "-v", "error", "-select_streams", "v:0",
307	             "-show_entries", "stream=r_frame_rate,width", "-of", "json", path],
308	            stderr=subprocess.DEVNULL).decode()
309	        st = (json.loads(out).get("streams") or [{}])[0]
310	        num, _, den = str(st.get("r_frame_rate", "0/1")).partition("/")
311	        fps = float(num) / float(den or "1")
312	        width = float(st.get("width") or 0)
313	        if fps > 0 and width > 0:
314	            return fps, width
315	    except (subprocess.SubprocessError, ValueError, KeyError, OSError, json.JSONDecodeError):
316	        pass
317	    return None

### What the RESULT contains — and the key mirroring caveat

`run_infer` returns a `ComputeResult` (`base.py:33-43`):

Fields: `returncode`, `outputs_uri`, `video_id`, `report` (the parsed `report.json` dict).

**The rally segments are NOT returned in-memory across the cloud boundary.** The dispatcher never sees the segment list as Python objects — it only:
- gets back the **summary `report.json`** (which has `segment_count` and a list of `{start, end}` only — no `shot_count`/`ending_reason`), and

## Summary for the API mirror

To mirror this path, the API must:
1. Set `deployment.compute_target=cloud_run` (and have `CLOUD_RUN_JOB`/`CLOUD_RUN_REGION`/`GOOGLE_CLOUD_PROJECT` in env), then build a `ComputeJobSpec(video_uri=<gs://in>, out_uri=<gs://out-root>, segmenter=..., config_overrides=...)` and call `get_compute_backend(config).run_infer(spec)` — or replicate `run_infer`'s dispatch+poll directly.
2. Treat the call as **async-but-blocking**: it dispatches a Cloud Run Job then bucket-polls a `{out_uri}/_dispatch/<token>.done` marker until done or `PolicyTimeout` (default 1800s wall budget). For a web API you will likely want to split dispatch from poll rather than block a request thread on `poll_until`.
3. On completion, take `result.video_id` + `result.outputs_uri` and **fetch `intervals.csv` from the bucket** to get the full rally segments (start/end/shot_count/ending_reason) — `result.report` only carries the coarse `{start,end}` summary, and nothing returns segments in-memory.
