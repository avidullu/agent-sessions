26	## 2. Two orthogonal axes — keep them separate
27	
28	```
29	WHERE the job runs            ┃   HOW a GPU stage executes on this box
30	(ComputeBackend — coarse,     ┃   (DeviceContext — fine, spec-aware,
31	 per-job: local | DO droplet  ┃    per-stage: probe the actual GPU →
32	 | serverless | byo_worker)   ┃    resolve batch/precision/chunk knobs)
33	        picks the machine ────╂──► on that machine, DeviceContext.detect()
34	                              ┃    probes the real GPU and tunes the work
35	```
36

38	this stage*.** A serverless L4, a DO RTX-4090 Droplet, and CPU CI each get correct knobs **automatically**,
39	with per-spec overrides available. Conflating the two is the main design trap.

42

147	- **`hosted`** — our GPU VM pool (the SaaS default).

149	  VM/GPU. **Critical security property:** the worker *pulls* jobs scoped to its tenant
150	  from the control plane, pulls input from the tenant's **own** storage, runs the
151	  pipeline, and writes artifacts + results back — so **the orchestrator never holds the
152	  user's cloud credentials** and needs **no inbound access** to their network. This

154	  outbound-only HTTPS long-poll). This pull-based runner is the **cheapest, most
155	  credential-safe v1** for BYO-compute.

157	  demand** (an academy with an AWS account but no standing GPU box), add **SkyPilot**
