## Segmenters subsystem

Two-stage rally-segmentation plugins. All concrete segmenters subclass `BasePlaySegmenter`, self-register into a module-level `segmenter_registry` at import time, and conform to one `process_video(...) -> List[Dict]` contract. The four "real" segmenters share a Phase 2 (local candidate generation) → Phase 3 (AI provider semantic confirmation) → Phase 4 (DB population) shape; only Phase 2 differs (person-motion vs shuttle-trajectory).

### Cross-cutting contracts / footguns (apply to all 4 AI segmenters)
- §**Window dict** (Phase 2 output, common): `{start, end, active_frame_count, peak_velocity, mean_velocity, track_id_count, chunk_index}`.
- §**AI segment dict** (provider output, keys read): `start_time, end_time, shuttle_exchange_count?, shot_count_confidence?`; segmenter injects `_candidate_id`.
- §**Return value** (all segmenters): `List[{id, start_time, end_time, duration, metadata}]` (+ `server, receiver` for motion only).
- §**DB API surface** used: `add_play_segment(video_id, start, end, server, receiver, metadata) -> segment_id`, `add_event(...)` (motion only), `add_candidate_segment(...) -> candidate_id` (hybrids only), `link_candidate_to_segment(candidate_id, segment_id)` (hybrids only).
- ⚠ All AI segmenters **return `[]` rather than raising** on: unknown sport, missing API key, unknown provider, invalid/zero `video_duration`, failed detector healthcheck/trajectory. Silent-degradation is the house style — callers must distinguish "no rallies" from "config error" out-of-band (logs only).
- ⚠ `_fmt_ts` is duplicated in 3 files (yolo/tracknet/wasb) — a refactor magnet.
- ⚠ tracknet/wasb reuse `log_yolo_candidates`/`store_yolo_candidates` config keys; renaming them would silently break those two segmenters' candidate persistence.
