## Summary
`security.upload_dir` defaulted to the CWD-relative `output/uploads` and was **never passed through the P0a app-home resolver** — only `output.output_dir` was resolved (`backend/main.py:1992`). So the packaged `indexer --app` (which `scripts/install.py` advertises as launchable from any shell) wrote browser uploads into whatever CWD the shell happened to have — or 500'd on an unwritable one — while the SQLite DB and reels correctly lived under `RALLY_APP_HOME`. Exactly the CWD-vs-app-home class of bug P0a was built to eliminate.

**Fix:** `backend/api/uploads.py::_upload_cfg` now resolves `upload_dir` through the same `resolve_output_dir` (`backend/utils/app_home.py`) used for `output.output_dir`, mirroring its semantics exactly:
- `RALLY_APP_HOME` **unset** → the configured value verbatim (CWD-relative, byte-identical to before — dev/repo/CI paths unchanged);
- **set** → a relative `upload_dir` (incl. the default) roots under the home (`<home>/output/uploads`);
- an **absolute** (or Windows drive-anchored) `upload_dir` always passes through untouched.

Resolving in `_upload_cfg` (rather than once in `main()`) keeps every entry point covered — including apps built via `create_app()` without going through `main()` — and `app_home()` is stable per-process, so the result is deterministic. Docs: `SecurityConfig.upload_dir` comment + `docs/CODE_MAP.md` §2.0 updated to match.

**Tests** (`tests/test_upload_download.py`, new P0a section):
- relative default resolves under the app home when `RALLY_APP_HOME` is set;
- absolute `upload_dir` passes through even with the env set;
- env unset → verbatim `output/uploads` (pins the unchanged pre-P0a default);
- end-to-end: init→part→complete from an arbitrary CWD lands the assembled file under `<home>/output/uploads` and leaks nothing into the launch CWD.

No existing test pinned the CWD-relative behavior of the *default* (the fixture uses an absolute `upload_dir`, which passes through unchanged), so no test needed loosening.
