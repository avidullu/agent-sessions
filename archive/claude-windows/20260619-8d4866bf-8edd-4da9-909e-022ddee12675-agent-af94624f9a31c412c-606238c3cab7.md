32	## The contract
33	```python
34	class WaitMode(str, Enum):
35	    WAIT_AND_RESUME = "wait_and_resume"   # DEFAULT — bounded wait; on deadline, persist + reschedule
36	    ABORT           = "abort"             # on deadline/hang, stop this op (fail or partial)
37	    BLOCK           = "block"             # legacy in-process bounded blocking wait (no reschedule)
38	
39	@dataclass(frozen=True)
40	class ExecutionPolicy:
41	    mode: WaitMode = WaitMode.WAIT_AND_RESUME
42	    poll_every_n_sec: float = 10.0        # cadence for polling an in-progress external op
43	    op_timeout_sec: float = 120.0         # HARD per-attempt deadline — the hang-killer (was missing)
44	    max_wait_sec: float = 1800.0          # total wall budget across resumes before giving up
45	    max_retries: int = 5                  # failures (not hangs); exponential backoff + jitter
46	    backoff_base_sec: float = 3.0
47	    on_timeout: Literal["reschedule", "partial", "fail"] = "reschedule"
48	    resumable: bool = True                # persist partial progress so a resume continues, not restarts
49	    # JSON-serializable → rides on the job row; a variant/job overrides any field.
50	```
51	- **`op_timeout_sec`** is the missing piece that would have killed the GX010125 hang: every external call
52	  (upload, `files.get`, `generate_content`) runs under a hard per-attempt deadline; on expiry the policy's
53	  `on_timeout` decides — `reschedule` (WAIT_AND_RESUME), `partial` (proceed with what's done), or `fail`.
54	- **Hang vs failure are distinct.** Retries (`max_retries` + backoff) handle a call that *errors*; the
55	  *timeout* handles a call that *hangs*. Both are policy, not provider-baked.
56	
57	## Self-scheduling mechanism (no master)
58	A long op under `WAIT_AND_RESUME`:
59	1. runs the external call under `op_timeout_sec`;
60	2. on success → record progress, continue;
61	3. on timeout/in-progress → **persist progress + `next_poll_at = now + poll_every_n_sec`, set job
62	   `status=waiting`, release the worker** (don't hold a thread sleeping for minutes);
63	4. the worker loop (and the startup sweep) claims jobs whose `next_poll_at <= now` and resumes them;
64	5. give up when cumulative wait > `max_wait_sec` → `on_timeout` terminal action.
65	
66	This needs **only** two `jobs`-table columns (`next_poll_at`, `progress` JSON — `progress` already exists)
67	and a "claim due jobs" query. No timer service, no leader, no master. On one box it is one worker draining a
68	priority-by-due-time queue; on many boxes it is the same query with a row-claim (`UPDATE … WHERE status=
69	'waiting' AND next_poll_at<=now`), so a job migrates to whoever is free.
70	
71	## Resumability (why WAIT_AND_RESUME is the default)

77	the opt-out for "good enough now" (what the one-off script does today).

93	## 6. Eval methodology change (gate the roadmap on this)
94	
95	Replace headline tIoU-F1 with a **task-faithful tolerance metric**:
96	
97	1. **Tolerance-match F1 (PRIMARY).** A prediction matches a reference iff `|Δstart| ≤ τ_start AND |Δend| ≤ τ_end`, asymmetric: **τ_start = 2.0s** (~2× the service-window/inter-annotator start noise; Gemini Δstart median 1.46s), **τ_end = 1.0–1.5s** (rally-end is a sharp event; Gemini Δend median 1.19s, and it's exactly where local fails at 3.12s). Freeze these as a documented decision in `docs/GOLDEN_REGRESSION_FIXTURES.md` with the IoU↔time derivation `Δ = D·(1−τ)/(1+τ)` recorded so the choice is auditable, until R6's inter-annotator study refines them.
98	2. **Over-segmentation guard (MANDATORY).** Strict one-to-one matching via **Hungarian global assignment, never greedy.** Report **P@τ = matched/n_pred** alongside **R@τ = matched/n_ref**. This makes the 222/165 = 1.35 surplus cost precision directly (mahadevpura-2: 40 preds vs 40 refs, 12 matched → P=0.30, R=0.30 — over-seg fully visible; widening τ can't hide it).
99	3. **Fragmentation/merge pair (SECOND guard, no-regression-gated per video).** split_count (predictions covering one reference — catches W1 over-seg) and merge_count (references under one prediction — catches the baseline mega-window pathology). **A promotion may not increase either guard on ANY video even if mean F1 rises** — this blocks the mahadevpura-0 trap (count parity improved 1.55→1.075 while gemini_only misses went 0→5).
100	4. **Boundary error as TWO separate distributions** (median + IQR of signed and absolute Δstart, Δend over matched pairs), never folded into one IoU. This is the metric that says start is solved and end is the open problem, and directs effort to the velocity-decay / net-crossing tail.
101	5. **tIoU/mIoU stays as a SECONDARY diagnostic** — single-number trend line, ties to the paper ablation backbone — but is **not the gate.**
102	
103	**Promotion (trustworthiness) rule at n=6–7:** a delta is promotable only if **(1)** the paired per-video sign-test on tolerance-F1 is a near-unanimous sweep — **6/0 at n=6 (p=0.031)** or **7/0 at n=7 (p=0.016)**; 5/1 or 6/1 is NOT significant (p=0.219 / 0.125); **AND (2)** over-seg and merge guards do not regress on any video; **AND (3)** the effect size is non-negligible (mean delta + bootstrap CI as an honesty band — expect it to span 0 at this n; use it to separate baseline→W1 +0.139 "real" from W1→W1+W2 +0.019 "directionally-clean-but-negligible," not as a pass/fail gate). **Stratify, don't blend:** report mahadevpura-1 as its own stratum.
