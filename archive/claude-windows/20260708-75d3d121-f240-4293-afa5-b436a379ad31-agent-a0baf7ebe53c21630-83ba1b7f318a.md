1160	+## 0. TL;DR
1161	+
1162	+The compile/stitch phase used to run **in-process on the CPU-only 2-vCPU control-plane**, where the
1163	+2026-07-08 live CUJ measured **~12m55s** for an 11-clip / ~80 s reel from a 1.83 GiB 4K source
1164	+(~45–90 s per ~7 s clip — the per-clip branding watermark forces a full 4K re-encode with **no
1165	+NVENC**). Validation (183 s) runs there too; both serialize on `_LOCAL_COMPUTE_LANE`, so one run pins
1166	+the control-plane for ~16 min → the API can't scale past a handful of concurrent users.
1167	+
1168	+#521 makes **where each pipeline phase runs a config edit, not a code change**, and moves the stitch
1169	+to the **L4 worker (NVENC + 8 vCPU)** the way detection already dispatches:
1170	+
1171	+1. **`deployment.phase_placement`** — a per-phase knob (`validation` / `segment` / `compile`) with
1172	+   values `control_plane | cloud_run_l4`. Unset ⇒ **today's placement, byte-identical**.
1173	+2. **compile → L4** — a `kind='compile'` Cloud Run dispatch mirroring the detect path: the
1174	+   control-plane resolves the reel's segments, stages a compile-spec to the bucket, dispatches
1175	+   `python -m backend.worker compile` on the L4, bucket-polls a done-marker, and returns the same
1176	+   `{status, filepath, download_url}` shape the SPA already expects.
1177	+3. **NVENC on the L4** — `deployment.cloud_stitch_encoder` (default `h264_nvenc`) is forwarded onto
1178	+   the worker's `stitching.encoder`; libx264 stays the everywhere-safe fallback (auto-probed).
1179	+
1180	+The cloud-serving preset opts compile onto the L4 (`phase_placement.compile=cloud_run_l4`).

1184	+## 1. The placement model
1185	+
1186	+`resolve_phase_placement(cfg, phase)` (in `backend/config/placement.py`) is the **single source of
1187	+truth** — orchestration and the worker never re-derive the mapping. Precedence: an explicit
1188	+`deployment.phase_placement.<phase>` wins; otherwise the **legacy default** reproduces pre-#521
1189	+behaviour exactly:
1190	+
1191	+| phase | knob unset (legacy default) | meaning |
1192	+|---|---|---|
1193	+| `validation` | `control_plane` | the authoritative gate (#512/#513) stays on the control-plane |
1194	+| `segment` (detect) | `cloud_run_l4` **iff** `compute_target==cloud_run`, else `control_plane` | today's DETECT dispatch |

1219	+## 2. compile → L4 dispatch (the flow)
1220	+
1221	+`orchestration._execute_compile` consults `resolve_phase_placement(cfg, "compile")`. When it resolves
1222	+to `cloud_run_l4` **and** cloud dispatch is available (`_cloud_available`), it calls
1223	+`_dispatch_compile_remote`; otherwise it stitches in-process via the shared `_stitch_reel` core
1224	+(unchanged).
1225	+
1226	+`_dispatch_compile_remote` (mirrors `_maybe_dispatch_remote`):
1227	+
1228	+1. **Resolve** the reel's segments HERE — the control-plane owns the DB (`_resolve_compile` →
1229	+   `(video, kept, out_name)`), applying the `stitching.min_shot_count` floor as before.
1230	+2. **Stage a compile-spec** to `<output_root>/_compile/<token>/spec.json` — the resolved
1231	+   `time_pairs`, the control-plane's resolved `stitching` config (watermark + padding, with `encoder`
1232	+   swapped to `cloud_stitch_encoder`), the source `video_uri`, `video_id`, `output_name`, `locale`.
1233	+   The worker therefore needs **no control-plane DB** — everything rides the spec.
1234	+3. **Dispatch** a `compile` Cloud Run Job execution (`CompileJobSpec` → `CloudRunCompute.run_compile`)
1235	+   running `python -m backend.worker compile --spec-uri … --done-uri … --set storage.output_root=…`,
1236	+   forwarding the bucket coordinates (the worker Job has no `DEPLOYMENT_PROFILE`).
1237	+4. **Bucket-poll** the done-marker at `<output_root>/_compile/<token>.done` — the SAME
1238	+   `_await_marker` machinery `run_infer` uses (crash-fast on a terminal-without-marker execution,
1239	+   rescue-or-cancel on a poll timeout). Distinct `_compile/` prefix so a compile and a detection for
1240	+   one bucket never collide on a marker.
1241	+5. The worker (`cmd_compile`) reads the spec, stitches the reel via the **shared `_stitch_reel`
1242	+   core** (no forked pipeline), mirror-uploads it to `<output_root>/highlights/<video_id>/<name>`,
1243	+   and writes the marker (rc + `download_url` + `reel_uri`).
1244	+6. The control-plane returns `{status, filepath, download_url, video_id}` — the reel is already in the
1245	+   bucket, so `/api/highlights` serves it via the existing signed-URL 307. On a worker rc≠0 →
1246	+   `status='failed'` with the worker's message (clean SPA verdict, never a crash).
1247	+
1248	+**Fallback:** if compile is placed on the L4 but the box isn't actually cloud-wired (no output bucket
1249	+/ Cloud Run env), `_dispatch_compile_remote` logs and stitches in-process — a slow reel beats no reel.

1253	+## 3. NVENC on the L4 — and the D5/D16(b) parity note
1254	+
1255	+The dominant term in the CUJ stitch was the **per-clip 4K re-encode** the branding watermark forces
1256	+(~67 s/clip on 2 vCPU with libx264). The L4 has a hardware H.264/HEVC encoder, so #521 adds an encoder
1257	+knob:
1258	+
1259	+- `StitchingConfig.encoder` — `libx264` (default, CPU, works everywhere incl. CI) | `h264_nvenc` |
1260	+  `hevc_nvenc`. `VideoCompiler` **probes** the requested encoder once per run (a 1-frame lavfi test
1261	+  encode) and **falls back to libx264** if this ffmpeg build can't run it, so a misconfig / non-GPU
1262	+  box never breaks. All clips share the one chosen encoder → the concat stays `-c copy`.
1263	+- `deployment.cloud_stitch_encoder` (default `h264_nvenc`) — what the compile-dispatch forwards onto
1264	+  the worker's `stitching.encoder` for the L4 run. Set it to `libx264` to run the L4 stitch on CPU.
1265	+- The control-plane's **own** local stitch always uses `stitching.encoder` (libx264 by default) — the
1266	+  CP has no GPU.
1267	+
1268	+**Parity note (honest):** [README.md](./README.md) **D5/D16(b)** kept stitch **encode = libx264** to
1269	+protect a byte-exact stitch parity guarantee, and explicitly **deferred NVENC encode behind a config
1270	+knob, "revisit only if M7 cost data justifies relaxing parity."** The 2026-07-08 CUJ (~13 min stitch,
1271	+a hard scaling wall past ~5 concurrent users) **is** that cost data. #521 lands exactly the deferred
1272	+shape — NVENC **behind a config knob**, libx264 the default, config-reversible per phase. Enabling
1273	+NVENC relaxes byte-identity **at the reel ENCODE layer only** (a cosmetic, shareable artifact); the
1274	+**WINDOW/rally-level parity** (the analytical output) is untouched — detection and windowing are
1275	+unchanged. If bit-exact reels are ever required, set `cloud_stitch_encoder=libx264`.
1276	+
1277	+> Follow-up (tracked, not in #521's first cut): a **pre-rendered / overlay-filter watermark** so the
1278	+> stitch isn't a full re-encode at all (the deeper win beyond swapping the encoder).

1282	+## 4. Validation placement + the "nobody validates" guard
1283	+
1284	+`phase_placement.validation` moves the CPU-bound validator suite off the 2-vCPU control-plane too,
1285	+via the existing `--skip-validation` lever (#513):
1286	+
1287	+- **`control_plane`** (default): the control-plane runs the validators and is the authoritative gate;
1288	+  the worker **skips** its redundant re-validation (`skip_validation=True`) — today's #512/#513
1289	+  behaviour, byte-identical.
1290	+- **`cloud_run_l4`**: when detection **actually** dispatches to the L4, the control-plane **delegates**
1291	+  — it does NOT run the validator suite (`_execute_processing` skips it), and the dispatch carries
1292	+  **no** `--skip-validation`, so the **worker** validates and rejects a bad clip via a non-zero rc
1293	+  (surfaced as a failed job).
1294	+
1295	+**Footgun guard:** a clip can only be validated on the worker if the worker also **detects** it there.
1296	+Two protections:
1297	+
1298	+1. **Config-load guard** (`DeploymentConfig` model-validator): `validation=cloud_run_l4` requires the
1299	+   effective segment placement to also be `cloud_run_l4` (explicit, or via `compute_target=cloud_run`)
1300	+   — else config load fails with an actionable error.
1301	+2. **Runtime guard** (`_will_detect_on_cloud`): if a per-request `compute='local'` forces detection
1302	+   in-process (no worker), the control-plane **still validates** — never leave a clip unvalidated
1303	+   because nobody ran the gate.
