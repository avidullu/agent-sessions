## What

`--output-dir` had argparse default `"output"` and was applied **unconditionally** at `main()` init (`backend/main.py`), so a config-set `output.output_dir` (the documented knob, `backend/config/models.py::OutputConfig`) could never take effect on the main entry path. The SQLite DB path derives from it, so the server silently created a fresh empty DB under `./output` while `run_eval.py`/`run_regression.py` (via `backend.config.default_db_path`) resolved the DB from config.json — split state / perceived data loss. (Audit finding R1-19, 2026-07-02.)

## How

- Argparse default is now `None` (= "not passed").
- New pure helper `backend/utils/paths.py::resolve_startup_output_dir(cli_output_dir, config)`: an **explicit** CLI `--output-dir` wins; otherwise config.json's `output.output_dir` is honored via the existing `output_base()`; **P0a app-home rooting** (`resolve_output_dir`) applies either way.
- Both `main()` call sites go through the helper: the init path **and** the debug-trim path (which resolved `args.output_dir` before config load — per the audit verifier notes it must handle the `None` default; it now falls back to the loaded config value).
- `OutputConfig.output_dir` comment corrected: the flag overrides only when actually passed.
- **Byte-identical default**: with neither knob set the result is `"output"` exactly as before; an explicit `--output-dir` behaves exactly as before.
