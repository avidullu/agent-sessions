"""Shared single-pass frame sampler for the frame-decoding validators.

Historically ``scene_cut``, ``blur`` and ``relevance`` each opened their **own**
``cv2.VideoCapture`` and pulled every sample frame via random access
(``cap.set(cv2.CAP_PROP_POS_FRAMES, idx)`` then ``cap.read()``). On long-GOP
HEVC / 4K footage (GoPro) decoded on a CPU-only control-plane, every
``POS_FRAMES`` seek forces FFmpeg to jump to the nearest keyframe and decode
forward, so ~125 seeks across **three** independent decode opens cost minutes
(observed 6m47s "Running validations" on a 1.41 GiB clip before segmentation
even started).

This module decodes the **same** sample indices in a single open with one
monotonic-forward pass:

* ``cap.grab()`` advances cheaply through the small gaps between the dense
  ``scene_cut`` samples (which cluster in the first ~50s), and
* a single forward ``POS_FRAMES`` seek skips the large gaps between the sparse
  whole-video ``blur`` / ``relevance`` samples (a bounded keyframe jump instead
  of decoding everything in between).

The frames handed to each validator are byte-identical to the old per-validator
seeks (verified against the reference clip), so pass/fail decisions are
unchanged — only the wall-clock collapses. Frames are **streamed**: at most one
decoded frame is held in memory at a time (each frame is dispatched to the
interested validators' online accumulators and then dropped), so a 4K clip does
not balloon RAM the way caching ~125 full-resolution frames would.

Why a hybrid (grab + occasional forward seek) rather than pure ``grab()``:
``blur``/``relevance`` sample right up to the end of the file, so a pure
forward ``grab()`` pass would decode the **whole** video — measured *slower*
than the seek-per-sample status quo on the 1.4 GiB reference clip (38s vs 27s).
The hybrid grabs only the dense region and forward-seeks the rest: ~8.6s on the
same clip, with 17 monotonic-forward seeks instead of 126 random ones.
"""

from __future__ import annotations

import logging
from collections import defaultdict
from dataclasses import dataclass
from typing import Any, Dict, List, Sequence, Tuple

import cv2

logger = logging.getLogger(__name__)

# Context keys populated by the registry's shared pre-pass and consumed by each
# FrameSamplingValidator.validate().
FRAME_META_KEY = "frame_sampler_meta"
FRAME_STATES_KEY = "frame_sampler_states"

# Grab through gaps up to ~2 seconds of frames (>= a long GoPro GOP); forward-seek
# anything larger. Below this a seek+keyframe-decode costs more than just grabbing
# the intervening frames, and it keeps the dense scene_cut region (samples ~0.5s
# apart) on the cheap sequential path.
_SEEK_GAP_FLOOR_FRAMES = 64


@dataclass
class SampleMeta:
    """Decode metadata read once from the shared capture (same source the old
    per-validator opens used: ``cv2.VideoCapture.get``)."""

    opened: bool
    fps: float
    total_frames: int


def _seek_gap_frames(fps: float) -> int:
    """Frame-gap threshold above which we forward-seek instead of grabbing."""
    if fps and fps > 0:
        return max(int(round(fps)) * 2, _SEEK_GAP_FLOOR_FRAMES)
    return _SEEK_GAP_FLOOR_FRAMES

        # e.g. frame 0). Sorted union drives one monotonic-forward pass.
        wanted: Dict[int, List[Any]] = defaultdict(list)
        for sampler in samplers:
            for idx in sampler.sample_indices(total_frames, fps):
                wanted[idx].append(sampler)

        _decode_and_dispatch(cap, sorted(wanted), wanted, states, fps)
        return meta, states
    finally:
        cap.release()


def _decode_and_dispatch(
    cap: Any,
    order: List[int],
    wanted: Dict[int, List[Any]],
    states: Dict[str, Any],
    fps: float,
) -> None:
    """One monotonic-forward pass; retrieve only at wanted indices and dispatch."""
    gap = _seek_gap_frames(fps)
    pos = 0
    for target in order:
        if target - pos > gap:
            # Skip a large gap with a single forward seek (bounded keyframe jump).
            cap.set(cv2.CAP_PROP_POS_FRAMES, target)
            pos = target
        else:
            # Grab (decode, no copy) forward through the small gap.
            while pos < target:
                if not cap.grab():
                    return  # EOF: no further sample index is reachable.
                pos += 1

        ok, frame = cap.read()  # grab + retrieve the wanted frame at pos == target
        if not ok:
            return  # EOF / undecodable tail: remaining indices are unreachable.
        for sampler in wanted[target]:
            sampler._consume(states[sampler.name], target, frame)
        pos = target + 1

# Correlation histogram threshold: 1.0 is a perfect match; < 0.6 flags a sudden
# massive scene change (a cut).
_CUT_THRESHOLD = 0.6
# Cap the number of samples so validation stays instant on long clips (the
# samples cover roughly the first 50 seconds at 2 fps).
_MAX_SAMPLES = 100


class SceneCutDensityValidator(FrameSamplingValidator):
    @property
    def name(self) -> str:
        return "scene_cut_check"

    @property
    def description(self) -> str:
        return "Analyzes visual frames to detect abrupt scene cuts, which indicate an edited or compiled video."

    def sample_indices(self, total_frames: int, fps: float) -> List[int]:
        # Sample at 2 frames per second (fps/2 step), capped at _MAX_SAMPLES.
        sample_interval = max(1, int(fps / 2))
        indices: List[int] = []
        frame_idx = 0
        sampled_count = 0
        while True:
            indices.append(frame_idx)
            sampled_count += 1
            frame_idx += sample_interval
            if frame_idx >= total_frames or sampled_count > _MAX_SAMPLES:
                break
        return indices

    def _init_state(self, config: Any) -> dict[str, Any]:
        return {"cuts_detected": 0, "sampled_count": 0, "prev_hist": None}

    def _consume(self, state: dict[str, Any], frame_idx: int, frame: Any) -> None:
        # Calculate color histogram (hue/saturation) and compare to the previous
        # sample; a big correlation drop is a cut.
        hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
        hist = cv2.calcHist([hsv], [0, 1], None, [50, 60], [0, 180, 0, 256])
        cv2.normalize(hist, hist, alpha=0, beta=1, norm_type=cv2.NORM_MINMAX)

        prev_hist = state["prev_hist"]
        if prev_hist is not None:
            score = cv2.compareHist(prev_hist, hist, cv2.HISTCMP_CORREL)
            if score < _CUT_THRESHOLD:
                state["cuts_detected"] += 1

        state["prev_hist"] = hist
        state["sampled_count"] += 1

    def _finalize(
        self, state: dict[str, Any], meta: SampleMeta, config: Any, context: dict
    ) -> ValidationResult:
        if not meta.opened:
            return ValidationResult(
                validator_name=self.name,
                passed=False,
                message="Failed to open video file using OpenCV.",
            )

        fps = meta.fps
        total_frames = meta.total_frames
        duration = total_frames / fps if fps > 0 else 0

        if duration <= 0:
            return ValidationResult(
                validator_name=self.name,
                passed=False,
                message="Invalid video duration.",
            )

        sample_interval = max(1, int(fps / 2))
        cuts_detected = state["cuts_detected"]
        sampled_count = state["sampled_count"]

        # Compute cuts per minute
        sampled_duration = (sampled_count * sample_interval) / fps if fps > 0 else 1
        cuts_per_minute = (
            (cuts_detected / sampled_duration) * 60 if sampled_duration > 0 else 0
        )

        details = {
            "cuts_detected": cuts_detected,
            "sampled_frames": sampled_count,
            "cuts_per_minute": round(cuts_per_minute, 3),
        }

        val_cfg = config.validation
        max_cuts_rate = val_cfg.max_scene_cuts_per_minute

        if cuts_per_minute > max_cuts_rate:
            return ValidationResult(
                validator_name=self.name,
                passed=False,
                message=f"Video splicing compromise: Detected {cuts_detected} cuts ({round(cuts_per_minute, 2)} cuts/min), which exceeds the continuous raw file limit of {max_cuts_rate} cuts/min.",
                details=details,
            )

        return ValidationResult(
            validator_name=self.name,
            passed=True,
            message="Scene continuity check passed. No abnormal visual cuts detected.",
            details=details,
        )

# In-memory fake VideoCapture: records opens, seeks, and retrieved frame indices.

def marker_frame(idx: int, h: int = 8, w: int = 8) -> np.ndarray:
    frame = np.zeros((h, w, 3), dtype=np.uint8)
    frame[0, 0] = [idx & 0xFF, (idx >> 8) & 0xFF, (idx >> 16) & 0xFF]
    return frame


def recover_marker(frame: np.ndarray) -> int:
    b, g, r = (int(x) for x in frame[0, 0])
    return b + (g << 8) + (r << 16)


class FakeCapture:
    """Mimics the tiny slice of cv2.VideoCapture the sampler uses."""

    def __init__(self, path, *, n, fps, opened, frame_fn, log):
        self.n = n
        self.fps = fps
        self._opened = opened
        self._frame_fn = frame_fn
        self.pos = 0
        self._last = None
        self.seeks: list[int] = []
        self.retrieved: list[int] = []
        self.released = False
        log.append(self)  # record this open

    def isOpened(self):
        return self._opened

    def get(self, prop):
        if prop == cv2.CAP_PROP_FPS:
            return self.fps
        if prop == cv2.CAP_PROP_FRAME_COUNT:
            return self.n
        return 0

    def set(self, prop, value):
        if prop == cv2.CAP_PROP_POS_FRAMES:
            self.pos = int(value)
            self.seeks.append(int(value))
        return True

    def grab(self):
        if self.pos >= self.n:
            return False
        self._last = self.pos
        self.pos += 1
        return True

    def retrieve(self):
        if self._last is None or self._last >= self.n:
            return False, None
        self.retrieved.append(self._last)
        return True, self._frame_fn(self._last)

    def read(self):
        if not self.grab():
            return False, None
        return self.retrieve()

    def release(self):
        self.released = True

## Problem

Video validation is pathologically slow on large GoPro clips on the hosted Cloud Run control-plane. Observed live 2026-07-07 (job `f29d41d0…`, "Video 1 - Badminton.MP4", 1.41 GiB, `rally-control-plane` asia-southeast1): the **"Running validations" phase took ~6m47s** (13:49:18 → 13:56:08) before segmentation even started.

**Root cause:** `scene_cut`, `blur`, and `relevance` each opened their **own** `cv2.VideoCapture` and sampled frames by random access — `cap.set(cv2.CAP_PROP_POS_FRAMES, idx)` then `cap.read()`. Counts: scene_cut ~101 samples, blur 15, relevance 10 → **~125 random seeks across 3 independent decode opens**. On long-GOP HEVC/4K (GoPro) decoded CPU-only, each `POS_FRAMES` seek forces FFmpeg to jump to the nearest keyframe and decode forward, so each seek can cost seconds. ~125 × seconds ≈ the 6.5 min observed.

## Fix

A **shared single decode pass** — `backend/pipeline/validators/frame_sampler.py` + a new `FrameSamplingValidator` base in `base.py`. The registry decodes every sampled frame **once** and **streams** each frame to the validators' online accumulators (one decoded frame held at a time). The three validators become `FrameSamplingValidator` subclasses declaring `sample_indices(total, fps)` and reducing via `_init_state` / `_consume` / `_finalize`; the registry runs the pass up front in `run_all_with_context`. Each validator still finalizes its own decision with full config/context, so ordering and semantics are preserved. A standalone `.validate()` call (no shared context) transparently falls back to its own single pass.

**One `VideoCapture`, monotonic-forward:** `grab()` (cheap) advances through the small gaps between scene_cut's dense samples; a **single forward `POS_FRAMES` seek** skips the large gaps between blur/relevance's sparse whole-video samples (a bounded keyframe jump instead of decoding everything between them).

### Why forward-hybrid rather than pure `grab()`-through

`grab()` is **not** free — it decodes. blur/relevance sample right up to end-of-file, so a pure forward `grab()` pass would decode the **whole** video. Measured on the reference clip that was **slower than the seek-per-sample status quo** (38.03s vs ~27–39s). The hybrid grabs only the dense region and forward-seeks the rest. See the table below.

### Streaming (memory)

Frames are dispatched to interested validators and dropped — at most one decoded frame in memory. Caching all ~125 full-res samples would be ~3 GB at 4K (OOM risk on the 2-vCPU control-plane).

## Summary

Follow-up to #512. That PR eliminated the seek-per-sample pathology in video validation (6m47s → single-digit seconds on a 1.4 GiB 1080p clip) via a shared, streaming, monotonic-forward decode pass that samples the **exact same frame indices** as before, so decisions are byte-identical. But it deliberately did **not** chase literal "a few seconds" on **true 4K** footage, because the only ways to get there change *which* frames are sampled (and therefore the pass/fail decisions). This issue tracks doing that properly.

## Why the residual cost exists

After #512, one shared forward pass still has to **decode `scene_cut`'s dense region** — ~100 samples at ~0.5s spacing over the first ~50s — to hit those exact indices. On a 4K HEVC clip on the 2-vCPU CPU-only control-plane, decoding ~50s of 4K sequentially is still tens of seconds. This is inherent to preserving the current sampling contract; you cannot get those specific frames faster without decoding through them.

Measured floor on the 1.4 GiB / 1080p60 / 29175-frame reference clip: **9.57s** (vs 38.98s old). 4K is materially heavier per frame; expect the residual to be worse there.

## Options (all change the sampled frames → require a decision-equivalence re-baseline)

1. **Keyframe-only sampling** — decode just I-frames (`ffmpeg -skip_frame nokey` / `-vf select='eq(pict_type,I)'`). The decoder skips P/B frames entirely, so an ~11-min GoPro clip (GOP ~1–4s) decodes only a few hundred frames → genuinely a few seconds. Sampling shifts from arbitrary indices to keyframe positions.
2. **Downscaled proxy** — run validation on the 720p (or smaller) proxy that already exists for detection (see `docs/COMPUTE_DECOUPLED_SERVING` / the 720p proxy work). ~10–20× cheaper decode; downscaling perturbs blur variance, court-green ratio, and the scene-cut histogram.
3. **Wall-clock cap / early-out** — a hard bound so validation can never dominate the request (truncates sampling → changes decisions when it fires). Useful as a safety net, not a primary path.

## Why this needs care (not a drop-in)

- Each option changes the frames fed to `blur` / `scene_cut` / `relevance`, so the thresholds (`min_blur_threshold`, `max_scene_cuts_per_minute`, relevance `court_pixels_min_ratio` / HSV bounds) must be **re-validated / re-tuned** against the new sample distribution, ideally on the golden corpus, to confirm equivalent accept/reject behavior on real footage.
- The #512 regression `tests/test_frame_sampler.py::test_sample_indices_match_legacy_*` intentionally pins the *current* indices; a change here will replace those with a new sampling contract + new equivalence tests.

## Acceptance

- [ ] Validation of a true-4K GoPro clip completes in **a few seconds** on the CPU-only control-plane.
- [ ] Accept/reject decisions on the golden corpus are **equivalent** to the current validators (documented delta if any threshold is re-tuned).
- [ ] New regression pins the chosen sampling contract (keyframe / proxy) and its decision-equivalence evidence.
- [ ] Decide whether to also add a wall-clock safety cap independent of the sampling change.
