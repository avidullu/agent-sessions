## Problem
`load_canonical_csv` (`src/parsers/cvat/rally_cvat.py`) silently dropped any rally whose `start_time` parses to exactly `0.0`. The cause was a falsy-zero `or` fallback:

```python
start = _parse_secs(row.get("start_time")) or _parse_secs(row.get("start_mmss"))
end   = _parse_secs(row.get("end_time"))   or _parse_secs(row.get("end_mmss"))
```

When `start_time` parses to `0.0`, `0.0 or _parse_secs(start_mmss)` evaluates to the second operand (`None` when there is no `start_mmss` column), so the row trips `if start is None: continue` and is skipped. A rally that legitimately starts at `0.0s` is lost — confirmed: a 3-row canonical CSV with row 1 at `start_time=0` loaded only 2 records.

## Fix
Prefer the decimal column, falling back to mm:ss only when the decimal is genuinely `None`:

```python
start = _parse_secs(row.get("start_time"))

end = _parse_secs(row.get("end_time"))
if end is None:
    end = _parse_secs(row.get("end_mmss"))
```
